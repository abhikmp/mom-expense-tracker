# App PIN Lock & Sensitive Data Protection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional 4–6 digit PIN lock with Master Password recovery that hides sensitive financial views/data until unlocked while keeping expense entry in **Record** frictionless, plus updated banner timings and 4-second delete **Undo**.

**Architecture:** Bump IndexedDB (`src/storage/db.ts`) from v1 to v2 with an isolated `security` object store holding salted PBKDF2-SHA256 hashes (`src/security/crypto.ts`) for PIN and Master Password, keeping `AppSettings` and `BackupPayload` untouched. Manage lock session state, >1-minute background auto-lock (`visibilitychange`/`pagehide`), 5-try 30s cooldown, banner timings, and delete-undo inside `AppContext`, and gate/mask views with a reusable `<LockedCard>` and accessible `<PinModal>`.

**Tech Stack:** React 19, TypeScript, Vite PWA, IndexedDB (`idb`), Web Crypto API (`crypto.subtle`), Phosphor Icons (`@phosphor-icons/react`), Vitest + React Testing Library + `fake-indexeddb`.

**Spec:** [docs/superpowers/specs/2026-11-27-pin-lock-design.md](../specs/2026-11-27-pin-lock-design.md) (and reference prototype [pin-lock-prototype.html](../specs/pin-lock-prototype.html))

## Global Constraints

- **Data preservation:** Upgrading IndexedDB `DB_VERSION` from `1` to `2` MUST NOT modify or clear existing `accounts`, `categories`, `transactions`, or `settings` stores. Existing installs without a `'lock'` record remain completely unlocked (`hasPin = false`).
- **Backup isolation:** `BackupPayload` MUST NOT include `security` records, and `restoreBackupAtomic` MUST NOT delete or overwrite the `security` store.
- **Credential rules:** PIN is 4–6 digits only (`^\d{4,6}$`); Master Password is any characters with length `>= 8`; never block paste on authentication inputs; never store plaintext secrets.
- **Auto-lock rule:** Re-lock ONLY on manual **Lock**, app close/reload, or > 1 minute (`> 60_000` ms) in the background—never an active-use idle timer.
- **Banner timings:** Transaction save banner = `2000` ms; general success status toasts = `2000` ms; no toast on PIN unlock; delete toast = red destructive styling with **Undo** button and `4000` ms auto-dismiss.
- **Accessibility & Styling:** Reuse `src/styles/tokens.css` Light/Dark tokens (`Soft Cards`), >= 44–48px touch targets, Phosphor icons (no emojis), modal focus trap + `Escape` dismissal + opener focus restoration.

## Review Focus

- **IndexedDB v1 → v2 upgrade on existing user data:** Upgrading a populated v1 database must create `security` without touching existing accounts, categories, transactions, or settings. *(Pinned in Task 1)*
- **Background timer clock edge cases (`<= 60_000` ms vs `> 60_000` ms, and repeated `hidden` events):** Briefly backgrounding for <= 60s must stay unlocked; backgrounding > 60s must lock, clear `lastDeletedTx`, close `EditTransactionDialog` / confirm dialogs, and redirect `bank-tx`/`all` to `home`. *(Pinned in Task 2 & Task 4)*
- **5-attempt cooldown vs. Forgot PIN escape hatch:** 5 consecutive wrong PINs must trigger a 30s PIN cooldown across Unlock/Change/Disable, while **Forgot PIN?** via Master Password stays usable immediately and clears the cooldown upon success. *(Pinned in Task 2 & Task 3)*
- **Paste & digit sanitization on PIN fields:** Pasting `"12a34"` or `" 567890 "` into a PIN input must not be blocked and must cleanly sanitize/enforce 4–6 digits without exceeding 6 digits. *(Pinned in Task 3)*
- **Delete Undo vs. Lock & Backup Count Integrity:** Undoing a delete within 4s restores the exact `Transaction` record in IndexedDB and state; locking during the 4s window immediately clears `lastDeletedTx` so it cannot be undone while locked. *(Pinned in Task 2)*

Key behaviors to implement cleanly:
- On init (`loadAppState`), also load `securityRecord = await loadSecurityRecord(db)` and store in state (`securityRecord: SecurityRecord | null`, `hasPin = securityRecord !== null`, `isUnlocked = false`).

  - On `document.visibilityState === 'visible'`: if `backgroundedAtRef.current !== null`, check `Date.now() - backgroundedAtRef.current > 60_000`; if true, call `lockApp('Auto-locked after being away for over 1 minute.')`, else clear `backgroundedAtRef.current = null`.
- Banner/toast timings:
  - `saveBanner` timeout = `2000` ms.
  - `statusToast` timeout = `statusToastDurationMs` (default `2000` ms for `'success'`; `4000` ms for delete toast even though its visual tone is `'error'`; genuine error toasts keep `durationMs = null` so they stay until dismissed).

- `undoDeleteTransaction()`: restores `lastDeletedTx` via `restoreDeletedTransactionAtomic(db, tx)`, adds it back to `transactions`, clears `lastDeletedTx`, and calls `showToast('Transaction restored and balances updated.', 'success')`.
- `recordTransaction`: if `!(hasPin && !isUnlocked)` navigate to `'home'`; if locked, stay on `'record'`.
- Failed PIN helper: increments `failedPinAttempts`; at `>= 5`, sets `pinCooldownUntil = Date.now() + 30_000`. Successful unlock or Master Password verification resets both to `0`.
